# ISS-0008 — Send reactions (tapbacks) from rx

GitHub: [#8 — Send reactions (tapbacks) from rx](https://github.com/humanitas-labs/rx/issues/8)

rx renders received tapbacks (netted) but cannot send them. Wanted: react to a message from rx (heart, thumbs up/down, ha ha, !!, ?, and custom emoji tapbacks).

Feasibility is the first gate — there is no supported path:

- The Messages scripting interface has no reaction verb; writing reaction rows into chat.db directly is off the table (read-only invariant, and a local-only row would not transmit anyway).
- Candidate 1: Shortcuts.app — check whether any Send Message / React action variant supports tapbacks (probably not, but cheap to verify).
- Candidate 2: UI scripting via Accessibility (System Events / AX API): locate the target message bubble in Messages.app, invoke the tapback context menu, press the reaction. Fragile across macOS releases, needs the Accessibility permission — but it is the same drive-the-real-app trust model as the send path, and the result is verifiable in chat.db (an `associated_message_type` row appears), so rx's source-verification model applies unchanged.
- Candidate 3: private frameworks (IMCore) — rejected; breaks the supported-surfaces-only line.

Plan: spike candidates 1 then 2; if 2 works, verified-reaction delivery mirrors the existing send verification (poll for the associated-message row).
