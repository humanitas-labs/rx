# ISS-0002 — File send via Messages.app scripting silently drops the attachment (macOS 26.5.1)

GitHub: [#2 — File send via Messages.app scripting silently drops the attachment (macOS 26.5.1)](https://github.com/humanitas-labs/rx/issues/2)

AppleScript `send (POSIX file …) to participant …` exits 0 and creates a message row whose decoded body is only the object-replacement placeholder (`￼`). No `attachment` or `message_attachment_join` row is created, no file lands under `~/Library/Messages/Attachments/`, and the self-chat echo also carries no attachment. Reproduced with .txt and .png payloads from two source directories. Text send through the same interface works and verifies against the source record.

Evidence: `docs/findings/platform-spike.md`, spike 3b.

Impact: v0 scope item “send one or more file attachments” (`docs/v0-scope.md` §4.4) currently has no working supported transport. rx's verification model correctly reports these sends as failed rather than falsely confirmed.

Candidate resolutions:
1. Test the Shortcuts.app “Send Message” action with an attachment as an alternative supported automation path.
2. Descope file sending from v0 (receiving/rendering attachments is unaffected).
3. UI automation — excluded by scope.
