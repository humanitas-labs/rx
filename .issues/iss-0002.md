# ISS-0002 — File send via Messages.app scripting silently drops the attachment (macOS 26.5.1)

GitHub: [#2 — File send via Messages.app scripting silently drops the attachment (macOS 26.5.1)](https://github.com/humanitas-labs/rx/issues/2)

AppleScript `send (POSIX file …) to participant …` exited successfully and
created a message row whose decoded body contained only the object-replacement
placeholder (`￼`). No `attachment` or `message_attachment_join` row was
created, no file appeared under `~/Library/Messages/Attachments/`, and the
self-chat echo also carried no attachment. The result was reproduced with text
and PNG payloads from two source directories. Text sending through the same
interface worked and verified against the source record.

The evidence applies to the participant-targeted self-chat route. The broader
chat-target and alias-coercion matrix remains tracked in #1.

Impact: file-attachment sending is excluded from v0 in `docs/spec/v0.md` §7.
Receiving and rendering attachments remains supported. rx's verification model
correctly reports a silent automation no-op as failed rather than delivered.

Resolution: file sending was descoped from v0. Future reconsideration proceeds
through #1 and production-adjacent live delivery tests; the retired platform
spike artifacts are not required.
