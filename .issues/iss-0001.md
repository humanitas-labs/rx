# ISS-0001 — Investigate AppleScript attachment sending by chat target and file coercion

GitHub: [#1 — Investigate AppleScript attachment sending by chat target and file coercion](https://github.com/humanitas-labs/rx/issues/1)

## Problem

Messages.app automation silently dropped attachments in the tested
participant-targeted self-chat route.

The tested AppleScript was:

```applescript
send (POSIX file file_path) to participant target of account id account_id
```

`osascript` exited successfully and created a placeholder message row, but no
attachment record, attachment join, or file under the Messages attachment
directory appeared within 60 seconds.

This proves that the tested participant/self-chat route failed. It does not
prove that file sending is generally broken on the current macOS release.

## Why this matters

rx sends through Messages.app and verifies delivery against the read-only
Messages database. Existing conversations are normally addressed by chat GUID,
which was not tested in the failed route.

File sending is excluded from v0. This issue preserves the narrower follow-up
needed before reconsidering that decision.

## Investigation

Run the following matrix with a valid PNG and a small text file:

| Target | File coercion | Conversation |
|---|---|---|
| Existing chat GUID | `POSIX file path` | Self-chat |
| Existing chat GUID | `POSIX file path as alias` | Self-chat |
| Account-qualified participant | `POSIX file path as alias` | Self-chat |
| Existing chat GUID | Both coercions | Controlled non-self chat |

For every attempt, preserve:

- exact AppleScript source and arguments;
- resolved target type and redacted identifier;
- pre-send maximum message row ID;
- `osascript` exit status and standard error;
- resulting outgoing message row and delivery fields;
- `message_attachment_join` and `attachment` results;
- whether the file appears in the Messages attachment directory; and
- elapsed time before verification terminates.

Add any future reproduction as a focused live test beside the production
delivery module. Do not recreate a general spike directory.

## Boundaries

- Do not write to `chat.db` or the Address Book database.
- Do not interpolate file paths or identifiers into AppleScript source; pass
  them as arguments.
- Do not send to another person without naming the controlled recipient first.
- Do not test Shortcuts or Accessibility automation until the supported
  chat-target and alias-coercion forms are resolved.
- Do not print message content, contact handles, or chat GUIDs in committed
  output.

## Done when

- The full matrix has reproducible production-adjacent test code and recorded
  results.
- We can state separately whether file sending works for existing chats and new
  participant-targeted conversations.
- Successful sends are verified by an attachment join in the intended chat.
- `docs/spec/v0.md` and this issue reflect the evidence.
- A future release has a supported implementation path or retains an explicit,
  evidence-backed deferral.
