# ISS-0017 — Conversation details card from the reader header

GitHub: [#17 — Conversation details card from the reader header](https://github.com/humanitas-labs/rx/issues/17)

The designed header control (centered name + chevron) is a conversation-details affordance. Today it opens the triage/actions menu (archive, snooze, Open in Messages, move to Space). That menu should stay on the row context menu, swipe, and palette.

Wanted: clicking the header opens a small details card.

**1:1**

- Resolved name, handles, contact photo when #11 lands.
- **Open in Contacts** — jump to that person's card in Contacts.app when a CNContact match exists; otherwise the row is omitted or disabled.
- **Open in Messages** — already implemented.

**Groups**

- Participant list (resolved names + handles).
- Open in Messages. No single Contacts destination unless we later add per-participant rows.

Destination is still slightly open — Contacts.app is the recommendation because Messages is already an escape hatch and the header is identity, not transport. Do not navigate to a raw `addressbook://` URL if it cannot select the card; prefer a helper/AppleScript show-contact that uses the Contacts identifier from the snapshot.

Triage stays off this surface. The calendar glyph (#9) is a sibling in the header, not inside this card.
