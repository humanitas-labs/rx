## Context

RX has no implementation or committed repository history. The approved product
direction is a macOS Apple Messages client with RX-owned archive and snooze,
not a unified inbox. The finished designs exist but have not yet been attached
to this repository or converted into an interaction inventory.

Apple Messages supplies canonical conversations and transport. On the current
development machine, its scripting dictionary exposes sending text and files
to chats or participants but no archive, snooze, or mark-read command. The
local Messages database contains the read model. RX must open it read-only and
store workflow state separately.

The existing `imsg` project proves several difficult mechanisms: read-only
database access, attributed-body decoding, Contacts resolution, attachment and
tapback parsing, unread queries, text delivery through Messages.app, and
source-record verification after send. That project is prior art, not the RX
application boundary.

The behavioral contract is [v0 scope](../docs/v0-scope.md). The proposed Electron
boundary is recorded in [ADR-002](../docs/decisions/002-electron-architecture.md).
Implementation does not begin until this plan, the scope, and ADR-002 are
approved. [ADR-001](../docs/decisions/001-application-architecture.md) preserves
the rejected Tauri proposal.

### 2. Prove the four platform-critical paths

**Files:** `spikes/apple-platform/`, `docs/findings/platform-spike.md`

Build throwaway command-line spike code before the application scaffold grows:

1. Open `chat.db` read-only and decode text from the 100 latest conversations.
2. Observe a new source message without polling the entire database and emit
   the affected chat GUID.
3. Send text and one file through Messages.app, then verify each resulting
   source row with the intended chat GUID.
4. Package a minimal signed Electron app and confirm Full Disk Access,
   Automation permission, and native-module loading under the packaged bundle
   identity.
5. Prove whether attributed-body decoding can be isolated as a decoder-only
   Node-API addon. Use a helper process only as the measured fallback.
6. Prove contact resolution through Apple’s Contacts framework from the
   packaged Electron application. Record direct read-only Address Book access
   only as a fallback if the supported framework cannot meet list latency.

Record latency, failure modes, database-lock behavior, macOS-version
assumptions, and whether source changes require WAL observation plus a bounded
poll fallback.

Do not copy the `imsg` architecture. Compare its working queries and delivery
checks after the RX interfaces have been defined. Reuse only the code that
reduces risk without importing CLI concepts.

**Exit:** all platform paths work from a packaged development build and the
native decoder boundary is settled. If any fails, revise ADR-002 before building
UI.

### 4. Implement the Apple source and decoder modules

**Files:** `apps/desktop/src/main/apple-messages/`,
`packages/apple-body-decoder/`, `packages/apple-contacts/`

Create a concrete Apple Messages module. Do not name it as a generic provider.

- `database`: open the selected Messages database with SQLite read-only flags;
  verify expected schema capabilities; expose no write handle.
- `identity`: use chat GUID and message GUID as durable source identifiers;
  treat SQLite row IDs as local incremental cursors only.
- `contacts`: resolve handles through an isolated Apple Contacts bridge, with
  Messages display names and raw handles as fallbacks. Do not read the Address
  Book database directly unless the platform spike records why the supported
  framework is insufficient.
- `conversations`: list summaries, participants, source unread metadata, and
  latest inbound identity.
- `messages`: page thread history and delegate attributed bodies to the narrow
  decoder boundary.
- `attachments`: resolve safe local attachment metadata and paths.
- `events`: observe source changes, advance a durable cursor, determine affected
  conversations, and publish typed domain events.
- `capabilities`: report missing permissions, schema drift, unavailable
  Messages.app, and unsupported payload types without crashing the UI.

The native decoder accepts a raw attributed-body payload and returns a typed
decoded result or explicit unsupported/error outcome. It has no filesystem,
database, network, workflow, Electron, or automation responsibility. If the
platform spike proves that shape infeasible, replace it with a long-lived,
supervised helper that exposes the same logical interface.

Queries accept bounded limits and never load the full message archive for a
normal screen. Unsupported rich messages produce a typed fallback item.

**Exit:** fixture tests cover every supported content type and a live diagnostic
can list conversation summaries without exposing content in logs.

### 5. Implement the RX workflow store and state machine

**Files:** `packages/core/src/workflow/`, `apps/desktop/migrations/`

Create a separate RX SQLite database. The initial schema contains:

```sql
CREATE TABLE conversation_state (
    chat_guid                  TEXT PRIMARY KEY,
    state                      TEXT NOT NULL CHECK (state IN ('inbox', 'archived', 'snoozed')),
    archived_through_guid      TEXT,
    snoozed_through_guid       TEXT,
    snoozed_until              INTEGER,
    seen_through_guid          TEXT,
    updated_at                 INTEGER NOT NULL,
    CHECK (
        (state = 'snoozed' AND snoozed_until IS NOT NULL)
        OR (state != 'snoozed' AND snoozed_until IS NULL)
    )
);

CREATE INDEX conversation_state_wake
ON conversation_state(state, snoozed_until);

CREATE TABLE spaces (
    id          INTEGER PRIMARY KEY,
    name        TEXT NOT NULL UNIQUE,
    position    INTEGER NOT NULL,
    created_at  INTEGER NOT NULL,
    updated_at  INTEGER NOT NULL
);

CREATE TABLE conversation_space (
    chat_guid   TEXT PRIMARY KEY,
    space_id    INTEGER NOT NULL REFERENCES spaces(id) ON DELETE CASCADE
);
```

A conversation with no `conversation_space` row is `Unassigned`; `All` is an
aggregate view, not a stored Space. Membership is single-primary by schema
(`chat_guid` is the primary key of the join table).

Model workflow state as a TypeScript discriminated union and expose explicit
transitions:

- `archive(chat, latest_inbound_guid)`;
- `snooze(chat, latest_inbound_guid, wake_at)`;
- `restore(chat)`;
- `mark_seen(chat, latest_message_guid)`;
- `receive_inbound(chat, message_guid)`; and
- `verify_outbound(chat, message_guid)`;
- `wake_due(now)`;
- `create_space(name)` / `rename_space(id, name)` / `reorder_space(id, position)`
  / `delete_space(id)`; and
- `assign_space(chat, space_id | none)`.

Space transitions never modify `conversation_state`: archive, snooze, unread,
and wake state survive a Space move. Deleting a Space returns its
conversations to `Unassigned` (delete the join rows, not the state rows).

Each transition is one database transaction and returns a typed outcome. A new
inbound GUID after the recorded archive or snooze watermark moves the
conversation to Inbox. A verified outbound message also restores an archived
or snoozed conversation; a failed attempt leaves its state unchanged. Due wakes
run at launch and at least once per minute.

Do not persist message bodies, attachment contents, participant names, or full
conversation summaries in the RX database.

**Exit:** table-driven tests cover every valid transition, restart recovery,
duplicate source events, clock boundaries, missing source conversations, and
idempotent replay.

### 6. Compose application read models

**Files:** `packages/core/src/application/`, `apps/desktop/src/shared/`,
`apps/desktop/src/main/ipc/`, `apps/desktop/src/preload/`

  assignment.
- Default conversations without RX state to Inbox, and conversations without a
  Space assignment to `Unassigned`.

- Derive RX unread from the latest source message and `seen_through_guid`.
- Expose typed commands for list, search, open thread, page older messages,

- Emit narrow events for conversation changes, workflow changes, permission
  changes, and delivery updates.
- Keep SQL rows, Apple parser types, native-decoder types, and automation details
  out of the renderer contract.
- Validate every IPC request and response at runtime. Expose named preload
  methods rather than raw `ipcRenderer` access.

**Exit:** integration tests run against fixtures and prove each list view,
ordering rule, and resurface rule.

## Verification

### Automated

- TypeScript typecheck and lint with zero warnings.
- Rust format, tests, and Clippy with warnings denied.
- Workflow state-machine table tests.
- Apple-source query and decoding tests against privacy-safe fixtures.
- Read-model integration tests for Inbox, Snoozed, Archive, search, unread, and
  resurface behavior.
- Contract tests across the Electron main/preload/renderer boundary.
- Security tests proving the renderer has no Node, filesystem, shell, database,
  or raw IPC access.
- UI tests for every path in the approved interaction inventory.
- Build and package from a clean checkout.

### Live platform checks

- Permission denied, granted, and revoked while RX is installed.
- Text and file delivery to an existing one-to-one conversation.
- Text delivery to an existing group.
- New one-to-one delivery to a resolved contact and explicit handle.
- Incoming message detection while RX is foregrounded and backgrounded.
- Archive and snooze resurfacing on real inbound messages.
- Snooze wake across app restart and Mac sleep.
- Source database remains read-only throughout the run.

### Dogfood stopping rule

The one-day test passes only with no missed actionable inbound message, wrong
recipient, false send confirmation, lost workflow state, or required parallel
reminder. A failure resets the test after correction. Cosmetic differences that
do not break a design-specified interaction are recorded for the next version.
